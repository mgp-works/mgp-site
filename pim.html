Pim

Problem

Pim added a core feature that auto-calculates medication and rest-cycle days by pill type, based on user feedback. As screens and components grew, the app's basic color-inversion approach for dark mode couldn't keep up—it didn't account for background/component hierarchy, causing readability issues and layout distortion. This led to undefined "exception" colors piling up in code, one-off manual design fixes, and repeated back-and-forth with engineers over unclear dark-mode behavior.

Solution

I built a Semantic Color System based on UI role rather than raw values:

  • Separated Primitive tokens (raw color scale) from Semantic tokens (named by role, e.g. bg.item.surface, mapped to the right value per light/dark mode)
  • Defined a property + target + role naming convention so new tokens stay predictable as the system scales
  • Replaced what would've required dozens of individual interaction-state colors with 3 reusable overlay tokens (bg.action)
  • Audited all color pairs against WCAG AA and fixed failures—e.g., CTA button contrast improved from 3.79:1 (fail) to 4.54:1 (pass)
  • Documented the full token system and usage rationale in a Figma guideline for engineers

Result

  • Light/dark mode now switches automatically with no manual color assignment
  • All temporary exception colors and inversion logic were removed, closing the design-code gap and creating a structure that can absorb future features without repeating the same scaling issues
  • All foreground/text elements now meet WCAG AA contrast (4.5:1+)
